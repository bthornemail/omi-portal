Computed Rows, Pure Functions, Omi-SlideRule, and the 0xAA55 Acceptance Seal

## 0. Core Correction

Omi-Gauge should not be defined as a static lookup table.

Omi-Gauge should be computed.

The row table exists, but it is not the authority. The table is the visible receipt of a computation.

The correct rule is:

    compute the row
    earn the position
    render through LUT
    accept by receipt

Not:

    define the character
    assign the meaning
    trust the table

This makes OMI deterministic.

Every row value is derived from the same folding law, not assigned by hand.

This means the system should be able to compute its own row tables, function scales, gauge orbit, and LUT projections before execution begins.

The pre-0xAA55 region is not passive data.

    0x00–0x0F = 1! .omi factorial row / source control
    0x10–0x1F = 2! .imo factorial row / runtime control
    0x20–0x2F = 3! .omi bridge row / BOM-pivot surface

The gauge alternates OMI/IMO chirality by factorial parity:

    1! OMI → 2! IMO → 3! OMI → 4! IMO →
    5! OMI → 6! IMO → 7! OMI → 8! IMO

Each row is a 2⁴ domain: high nibble = factorial row, low nibble = local slot.

### Two-Cube Mirror

Every byte in the gauge can be written 0xNM (N = row, M = slot). The mirror relation is:

    0xNM ↔ 0xMN

This defines the two-cube: the diagonal (0x00, 0x11, ..., 0xFF) is identity; the 240 off-diagonal cells form the transition/bridge surface.

The first control split is:

    .omi = 0x00–0x0F    .imo = 0x10–0x1F
    imo = omi XOR 0x10

So 0x10 is the first OMI/IMO domain toggle.

The 0x20 Bridge Order Marker folds hidden controls into readable notation:

    0x00–0x0F ↔ 0x20–0x2F    0x10–0x1F ↔ 0x30–0x3F
    0x40–0x4F ↔ 0x60–0x6F    0x50–0x5F ↔ 0x70–0x7F

Thus 1! ↔ 3!, 2! ↔ 4!, 5! ↔ 7!, 6! ↔ 8! under BOM XOR.

Canon:

> Everything before 0xAA55 must be computable from the gauge law.

## 9. Computed Omi-SlideRule

Omi-SlideRule should not be a manual list of scales.

It should be a pure-function table generated from the scale row.

A minimal interface:

    slide(scale, a, b, mode) → result

Where:

    scale = 0x30–0x3F
    a     = first relation value
    b     = second relation value
    mode  = forward / inverse / folded / periodic

Examples:

    slide(0x31, a, b, forward) = log(a) + log(b)
    slide(0x35, a, _, inverse) = reciprocal(a)
    slide(0x3C, a, _, forward) = sexagesimal(a)
    slide(0x3E, a, b, forward) = a² - b²
    slide(0x3F, n, _, forward) = 2ⁿ - 1

But in strict OMI, these can be symbolic rewrites instead of floating-point calculations.

Canon:

> Omi-SlideRule computes symbolic scale alignment. It does not require floating-point approximation.

## 10. Computed Omi-Gauge Table

A minimal interface:

    gauge(row, x, y) → cell

with:

    row ∈ 0..15
    x   ∈ 0..63
    y   ∈ 0..63

Formula:

    cell = (row << 12) | (x << 6) | y

This yields:

    0..65535

The inverse is:

    row = cell >> 12
    x   = (cell >> 6) & 0x3F
    y   = cell & 0x3F

This is exact.

No floating point.

No loss.

Canon:

> Omi-Gauge is an exact reversible addressing function over a 2¹⁶ plane.
