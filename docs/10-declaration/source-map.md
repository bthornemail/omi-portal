# OMI Documentation Source Map

This file is the canonical source and provenance index. The exploratory `dev-docs/` folder remains in the workspace as reference material, but canonical documentation authority lives in root doctrine files, `docs/`, the declarative `.omi` roots, and the structured manifest.

## Current Canonical Sources

- [OMI Manifesto](../../MANIFESTO.md): foundational orientation that OMI collapses representation and interpretation; notation is cipher and computation is rewrite of interpretation rather than mutation of data.
- [OMI Doctrine](../../DOCTRINE.md): canonical doctrine for OMI as rewrite topology; separates the notation-cipher invariant from derived geometries and implementation substrates.
- [OMI Native Gauge Canon](../omi-native-gauge-consolidated-canon.md): current native gauge, Omicron chirality, receipt model, and CIDR-retirement authority.
- [OMI Object Model](../omi-object-model.md): top-level declaration of browser surfaces, Lisp transformers, routing semantics, receipt paths, and runtime projections.
- [OMI Core Spec](../03-network/omi-core-spec.md): adapter-era implementation substrate for printable 8-segment ids, `data-omi-address`, and CSSOM selectors; subordinate to native gauge doctrine.
- [Canonical Addressing](../03-network/canonical-addressing.md): current address-root and adapter boundary summary.
- [OMI File Format](../06-presentation/omi-file-format.md): binary `car` pre-header and printable dot-delimited `cdr` payload.
- [OMI Protocol Sequencing](../04-transport/omi-protocol-sequencing.md): phase ordering across editor, memory, transport, GPU, and lifecycle surfaces.
- [OMI Object Model Manifest](omi-object-model.manifest.json): machine-readable declaration used by documentation integrity tests.

## Historical Note

Some manifest `sources` entries name `dev-docs/*.md` paths to preserve curated provenance. `dev-docs/_temp/` remains a research inbox and is not canonical authority. New implementation and documentation work should cite the canonical files above.
